# Three-method Guard revision — 2026-10-09

Node layout stays in upstream intrusive traits. The previous domain trait and
associated guard are replaced by `Guard::{protect, unpin, retire}` and a normal
factory closure. Both facades still share the intrusive core; values still return
immediately and cache only reclaimed empty blocks.

## Validation

- Default/no-default-feature all-target runs: 39 unit/integration tests each,
  plus benchmark smoke checks. Three rustdoc tests pass in each feature mode.
- Formatting, Clippy with warnings denied in both modes, warning-free rustdoc,
  Rust 1.85 library checks in both modes, and both examples pass.
- Full Miri: 38 passed, one existing large hardware stress case intentionally
  ignored, using the repository's Tree Borrows / permissive provenance /
  ignore-global-collector-leaks settings.
- All 8 custom guard tests also pass with **strict provenance and leak checking**.
  The final targeted rerun strengthens domain lifetime coverage by dropping the
  stack and external domain handle before retiring on another thread.
- The independent hazard fixture is deliberately !Send/!Sync and has **no Drop
  cleanup**: the tests depend on the stack calling `unpin`. Coverage includes
  normal/empty/closed exits, protection panic, idempotent unpin and reentry,
  replacement protection, tagged link identity distinct from the container,
  synchronous retirement, callback panic/reinsertion, and concurrent reuse.
  Borrowed/non-Send values and custom upstream atomic links remain supported.

These checks support the safety argument; they are not a proof. The hazard
fixture uses a mutex and is not a production lock-free hazard implementation.

## Allocation

The unchanged controlled batching instrument still reports 4,096 pushes with
4,096 node allocations at cache capacity zero, versus 32 at capacity 64.
Retirement profiling with 65,536 nodes and an old reader pinned reports:

| Operation | Allocations | Bytes |
|---|---:|---:|
| Intrusive push | 0 | 0 |
| Intrusive pop + defer | 1,023 | 2,119,656 |
| Value push (old reader prevents cache reuse) | 65,536 | 1,048,576 |
| Value pop | 1,023 | 2,119,656 |

The 1,023 allocations are amortized EBR bags, not one callback allocation per
node. Shared factory allocation is a construction cost outside these measured
operations. Ready-cache bounds still do not bound pending retirement backlog.

## Throughput relative to the previous PR revision

Baseline is **e2e94cc**, the preceding `Reclaimer` draft, not published 0.3.1.
Candidate is this three-method Guard revision. The older 0.3.1 comparison remains
in [the historical report](2026-10-09-reclaimer.md).

Both revisions use the identical intrusive benchmark and dependency lockfile,
Rust 1.93.0, Linux x86_64 on AMD EPYC 9V74, with an 8-CPU cgroup quota. Executable
hashes and source checksums are recorded in [environment.json](2026-10-09-guard/environment.json).
Builds and tests finished before throughput measurements. No CPU affinity or
frequency controls; host activity is uncontrolled. Each case includes thread
creation, teardown, epoch callback delivery and ID validation, as in the previous
report. Value workloads do not wait for empty storage reclamation.

First run is before then after, 20 samples, 0.5 s warmup and 1 s requested
measurement. Rates below are operations / Criterion mean time in **million
completed operations per second**:

Selected apparent losses were repeated in reverse order (Guard then before),
with 1 s warmup and 3 s requested measurement, still 20 samples. The unchanged
mutex case is retained as a control:

| Case | Before | Guard | Change |
|---|---:|---:|---:|
| epoch_transfer/intrusive/1p_1c | 6.40 | 5.94 | -7.2% |
| epoch_transfer/intrusive/4p_4c | 8.53 | 5.34 | -37.4% |
| epoch_transfer/mutex_vec/4p_4c | 3.83 | 3.34 | -12.8% |
| epoch_transfer/value_stack/8p_8c | 4.64 | 5.89 | +27.0% |

The intrusive transfer cases remain slower, by about 7% and 37% in this repeat.
The unchanged mutex control is also about 13% slower, showing environmental
variation. The value 8p/8c loss reverses in the repeat. Do not treat these numbers
as hardware-independent effects or aggregate them into one overall speedup.

The new shared factory keeps the domain alive for cross-thread retired tokens;
it adds atomic reference-count operations to intrusive removal/delivery and
indirect calls to guard creation. These are concrete costs of this design, but
this experiment does not isolate how much of each observed difference they
cause. **This revision does not establish throughput parity**. The API/safety
simplification is complete; performance-sensitive users should evaluate this
remaining cost on their own workloads.

Raw estimates and samples for every case, including slower outcomes, are in
[results.json](2026-10-09-guard/results.json); text logs are alongside it.
Within-run confidence intervals do not describe between-run host variation.

## Reproduce

Build each revision separately (avoid reusing stale local-package artifacts
across worktrees), keep identical Cargo.lock contents, then run sequentially:

```sh
cargo bench --bench intrusive_bench -- --noplot --sample-size 20 --warm-up-time 0.5 --measurement-time 1 --save-baseline guard_after
cargo bench --bench intrusive_bench -- --noplot --sample-size 20 --warm-up-time 1 --measurement-time 3 --save-baseline guard_verify_after 'epoch_transfer/intrusive/(1p_1c|4p_4c)|epoch_transfer/value_stack/8p_8c|epoch_transfer/mutex_vec/4p_4c'
cargo bench --bench cache_profile
cargo bench --bench retirement_profile -- intrusive
cargo bench --bench retirement_profile -- value
```

Use the `*_before` labels on e2e94cc. See [CONTRIBUTING](../../CONTRIBUTING.md)
for test and Miri commands.
